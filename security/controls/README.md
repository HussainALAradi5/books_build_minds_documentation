# Implemented security controls

| Area | Enforcement | Relevant code |
| --- | --- | --- |
| Authentication | HS256 JWTs expire after eight hours. Each authenticated request reloads the user and rejects inactive, archived, or deleted accounts. | [Server security](https://github.com/HussainALAradi5/books_build_minds_server/blob/main/utils/security.py) |
| Passwords | Registration hashes passwords with Werkzeug. Login verifies the hash; registration always creates a client role regardless of submitted role fields. | [Account service](https://github.com/HussainALAradi5/books_build_minds_server/blob/main/services/account_service.py) |
| Browser session | JWT and user ID cookies are HttpOnly, SameSite=Lax, path `/`, with Secure enabled in production. Session lookup verifies the profile with the server. | [Cookie settings](https://github.com/HussainALAradi5/books_build_minds_client_side/blob/main/src/lib/security.ts), [session lookup](https://github.com/HussainALAradi5/books_build_minds_client_side/blob/main/src/lib/session.ts) |
| Protected pages | Profile requires a valid session. Admin and access pages require the administrator account role and the relevant permission. | [Admin view](https://github.com/HussainALAradi5/books_build_minds_client_side/blob/main/src/features/admin/AdminView.tsx), [access view](https://github.com/HussainALAradi5/books_build_minds_client_side/blob/main/src/features/admin/AccessAdminView.tsx) |
| Authorization | `all_of`, `any_of`, `owns`, `purchased`, and role checks compose server policies. Unknown rule types fail closed. Database roles/groups are evaluated on requests. | [Access rules](https://github.com/HussainALAradi5/books_build_minds_server/blob/main/utils/access.py) |
| Book changes | Creation, editing, deletion, import, bulk changes, and book-image uploads require both the admin account role and their action permission. A delegated permission alone cannot bypass this role requirement. | [Book routes](https://github.com/HussainALAradi5/books_build_minds_server/blob/main/controllers/books.py), [media routes](https://github.com/HussainALAradi5/books_build_minds_server/blob/main/controllers/media.py) |
| Review changes | Creation requires purchase. Only the author can edit with the own-action permission. The author or an administrator can soft delete with the matching delete permission. Review ID must belong to the book slug. | [Review service](https://github.com/HussainALAradi5/books_build_minds_server/blob/main/services/reviews/review_service.py) |
| Receipts | The authenticated purchaser must have an active receipt for that book. The service uses the authenticated user's ID. | [Receipt service](https://github.com/HussainALAradi5/books_build_minds_server/blob/main/services/receipts/receipt_service.py) |
| Uploads | Server verifies decoded image formats, uses generated filenames, limits file size to 5 MB, limits book batches to 10, and caps request bodies at 25 MB. Profile uploads require exactly one image. | [Media validation](https://github.com/HussainALAradi5/books_build_minds_server/blob/main/services/media_service.py), [configuration](https://github.com/HussainALAradi5/books_build_minds_server/blob/main/config.py) |
| WebSockets | Book rooms are public for visible books and emit only a slug and resource name. Mutations remain authenticated HTTP requests. Socket origins are configured explicitly. | [Events](https://github.com/HussainALAradi5/books_build_minds_server/blob/main/utils/book_events.py), [application](https://github.com/HussainALAradi5/books_build_minds_server/blob/main/app.py) |
| API responses | API responses are marked no-store. Server adds nosniff and a referrer policy. | [Application headers](https://github.com/HussainALAradi5/books_build_minds_server/blob/main/app.py) |

Tabs and guides provide no authorization. Hiding a tab does not stop a direct API call, and a disabled button is not an access check. Guide content is authored as plain strings and rendered as text; no HTML parsing is used. The guide never invokes a mutation service.

Custom roles may grant supported read or member actions. They do not promote the account role. Review edits still require authorship, review moderation deletion still requires authorship or the admin role, and book changes require the admin role. Access management itself always requires the admin account role.

Uploaded images are served as public static media. They must not contain confidential information. An image disappearing from a UI or a soft-deleted record does not revoke access to an already known static file URL.
